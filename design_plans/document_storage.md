# Design Plan: Document Storage

**Document Version:** 1.0
**Feature:** Document Storage (MVP)
**Audience:** Engineering team, tech lead

---

## 1. Objective

Implement secure per-patient document storage supporting upload, metadata tagging, inline viewing, and access-controlled download. Files are stored in Supabase Storage (S3-compatible object store), never exposed via public URLs, and always accessed through short-lived signed URLs generated by the backend. The system must enforce an allow-list of MIME types, a 50 MB size cap, sanitise file names, and restrict deletion to the dentist role. The design must be robust against mid-upload failures and must not store partial files.

## 4. Data Model

### Table: `documents`

```sql
CREATE TABLE documents (
    id             UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    patient_id     UUID NOT NULL REFERENCES patients(id),
    appointment_id UUID REFERENCES appointments(id),
    treatment_id   UUID REFERENCES treatments(id),
    document_type  TEXT NOT NULL CHECK (document_type IN (
                     'xray', 'photo', 'consent_form',
                     'prescription', 'lab_report', 'other'
                   )),
    file_name      TEXT NOT NULL,              -- original sanitised filename
    storage_path   TEXT NOT NULL UNIQUE,       -- Supabase Storage object path
    file_size      BIGINT NOT NULL,            -- bytes
    mime_type      TEXT NOT NULL,              -- detected MIME, not client-supplied
    notes          TEXT,
    has_thumbnail  BOOLEAN NOT NULL DEFAULT FALSE,
    thumbnail_path TEXT,                       -- Storage path for thumbnail
    uploaded_by    UUID NOT NULL REFERENCES users(id),
    uploaded_at    TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_docs_patient      ON documents(patient_id);
CREATE INDEX idx_docs_appointment  ON documents(appointment_id);
CREATE INDEX idx_docs_type         ON documents(patient_id, document_type);
CREATE INDEX idx_docs_uploaded_at  ON documents(patient_id, uploaded_at DESC);
```

## 5. Core Design Decisions

### 5.1 MIME Type Detection via `python-magic`, Not Client Headers

**Decision:** The server detects the actual MIME type from the file's byte signature using `python-magic` (libmagic bindings) rather than trusting the `Content-Type` header or file extension supplied by the client.

**Rationale:** An attacker can rename a `.exe` to `.jpg` and set `Content-Type: image/jpeg`. File magic bytes cannot be trivially faked. This is the primary defence against uploading malicious files.

```python
import magic

async def detect_mime(file: UploadFile) -> str:
    header_bytes = await file.read(2048)   # read first 2KB for detection
    await file.seek(0)                      # reset for subsequent read
    mime = magic.from_buffer(header_bytes, mime=True)
    if mime not in ALLOWED_MIME_TYPES:
        raise HTTPException(415, f"File type '{mime}' is not allowed.")
    return mime
```

### 5.2 Atomic Upload: Validate Before Storing

**Decision:** Full validation (MIME type, file size) is performed before any write to Supabase Storage. If validation fails, no storage write occurs.

**Rationale:** Prevents partial/invalid files from appearing in storage. If the storage write succeeds but the DB insert fails, a cleanup task removes the orphaned file.

**Upload sequence:**
1. Read file into memory (or stream, if large)
2. Check file size ≤ 50 MB
3. Detect MIME type (magic bytes)
4. Sanitise filename
5. Generate storage path: `{patient_id}/{uuid}_{safe_filename}`
6. Upload to Supabase Storage
7. Generate thumbnail (if image)
8. `INSERT` into `documents` table
9. If step 8 fails → delete uploaded file from storage (compensating action)

### 5.3 Signed URLs, Never Direct Object URLs

**Decision:** Files in the `patient-docs` bucket are private. The backend generates a signed URL with a 15-minute expiry for every document access. No permanent public URL is ever issued.

**Rationale:** Patient radiographs and consent forms are sensitive. A leaked URL should not remain valid indefinitely. 15 minutes is sufficient for a user to view or download the file.

```python
async def get_signed_url(storage_path: str, expires_in: int = 900) -> str:
    response = await supabase.storage.from_("patient-docs") \
        .create_signed_url(storage_path, expires_in)
    return response["signedURL"]
```

### 5.4 Thumbnail Generation at Upload Time

**Decision:** Image thumbnails (max 400px longest side, JPEG quality 75) are generated at upload time using Pillow and stored as a separate object in the same bucket (`{path}_thumb.jpg`). The `has_thumbnail` flag in the DB indicates availability.

**Rationale:** Thumbnail generation on every gallery load would be expensive. Pre-generating at upload amortises the cost and keeps the gallery load fast.

**Exception:** DICOM files do not get a thumbnail (Pillow cannot render DICOM without additional libraries). `has_thumbnail = false` for DICOM uploads.

### 5.5 File Name Sanitisation

**Decision:** Use `werkzeug.utils.secure_filename()` to strip path components, null bytes, and special characters from the original file name before storage.

```python
from werkzeug.utils import secure_filename

safe_name = secure_filename(file.filename)  # e.g., "bitewing right.jpg" → "bitewing_right.jpg"
storage_path = f"{patient_id}/{uuid4()}_{safe_name}"
```

### Definition of Done

- [ ] A JPEG, PNG, PDF upload succeeds; file appears in gallery with thumbnail.
- [ ] A `.exe` file upload is rejected with HTTP 415 regardless of the filename extension.
- [ ] A file over 50 MB is rejected before reaching the storage layer.
- [ ] Signed URLs expire after 15 minutes (verified by waiting and re-fetching).
- [ ] A receptionist cannot see or trigger the delete action on any document.
- [ ] Storage path cannot be guessed — contains UUID prefix to prevent enumeration.
- [ ] If DB insert fails after storage upload, the file is deleted from storage (no orphans).
- [ ] DICOM files are accepted, stored, and a download link is provided with no thumbnail.
